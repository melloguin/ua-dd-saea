## 3. As 2 decisões deferidas pelo R1-00 — resolvidas

**(D61) evalFcn de LOTE com hard-stop no meio.** `c217_batch_eval(X, bud, evalFcnPerX)`: o UserProblem
(`once=true`) chama com um lote N×D; itero as linhas por `bud.evaluate` (cache-hit=0 FE, D89). Quando
o saldo zera, o `bud` levanta `MException('PlatEMO:Termination')` **no meio do lote** (D61) → propaga
por `CallFcn` (o `addCause` **preserva o identifier**) → `Solve` engole → **FE final = 31D−1 EXATO**.

> ⚠ **Achado desta sessão (o pattern-setter fecha isto para TODOS os PlatEMO):** o `obj.FE` nativo
> soma `length(Population)` **incluindo cache-hits** → a cada duplicata de infill ele **avança à
> frente do saldo distinto** (`bud.fe`). Com `Problem.maxFE=31D−1`, o `NotTerminated` do PlatEMO
> paral o run quando `obj.FE=31D−1` mas `bud.fe<31D−1` → ① curta → **gate REPROVA** (ZDT1 fechou 926).
> É exatamente o que a **D89** proíbe ("o `obj.FE` NÃO governa; o hard-stop é do wrapper"). **Fix:**
> `Problem.FE = Problem.data.bud.fe;` após cada infill (PCS:56) — re-sincroniza o contador nativo com
> o **saldo DISTINTO** do wrapper. Assim (a) o `NotTerminated` para em `bud.fe=31D−1`, (b) o `rate =
> Problem.FE/maxFE` fica fiel, (c) o hard-stop real segue sendo o throw do `bud`. **Todo algoritmo
> PlatEMO que possa propor duplicatas herda este sync.** Prova: ZDT1 (4 cache_hits) → 926→**929**.

**(③ `real_solution_id` nullable).** O c217 grava ③ **só dos candidatos SELECIONADOS** (o lote de
infill), que são avaliados no ciclo → têm `solution_id` → `real_solution_id` **SEMPRE presente →
int32** (casa com §17.2, sem tipo variável entre runs). O fallback `double+NaN` do `write_surrogate`
(R1-00) fica para algoritmos que gravem candidatos NÃO-avaliados (NULL); o c217 não precisa dele.

## 4. Receita N.0 do Solve real (o que os outros MATLAB herdam)

1. `bud = FEBudget(D, 31D−1, 11D−1, logger)` **criado ANTES** do `Problem`. O probe do construtor
   (`Initialization(1)`) usa `initFcn = @(N,~)X0(1:N,:)` → avalia **DoE[0]** (não um ponto aleatório),
   que o lote-init reencontra como **cache-hit** → `obj.FE==bud.fe`, ① com exatamente 31D−1 linhas,
   **sem poluir** o catálogo. (Padrão reutilizável: probe absorvido, não descartado.)
2. `UserProblem('evalFcn',@batch,'initFcn',@(N,~)X0(1:N,:),'D',D,'lower',xl,'upper',xu,
   'maxFE',31D−1,'N',50,'once',true,'data',struct(X0,buf,bud,log,…))`. `maxRuntime` fica `inf` (N.0.5).
   O `data` carrega **X0** (injeção) + **buf/bud/log** (a instrumentação lê `Problem.data.*`).
3. `rng(semente,'twister')` **DEPOIS** do Problem, **ANTES** do Solve (D59). (O probe não consome RNG —
   `initFcn` determinístico.)
4. `PCSAEA('parameter',{0.8,3000},'save',-K,'outputFcn',@(A,P) hook_output(A,P,buf,bud,[]))` +
   `try Solve catch PlatEMO:Termination`. O `hook_output` emite **②** (membership) por geração; erro
   REAL da ponte é rethrow → falha honesta.
5. `addpath(genpath(PLATEMO))` por worker (o despachante já faz; `run_c217` tem a rede p/ chamada direta).
